비전문가도 3D 공간에서 로봇 설치 공장을 직관적으로 구성할 수 있도록, Tool·Fixture·Carriage 객체의 업로드·등록·조작 흐름을 새로 설계하고, 실시간 3D 미리보기(Draft) 기능을 도입해 반복 작업을 제거한 프로젝트입니다.

01

배경 · Background

PM 1명(기여도 100%), FE 개발자 1명, BE 개발자 1명, 코어엔진팀 2명, UX디자이너 1명과 함께 2026년 6월부터 8월까지 진행한 프로젝트입니다. 기존 Factory Builder의 3D View는 Station·Robot 범위까지만 노출을 지원하여, 로봇에 부착되는 Tool(엔드이펙터)이나 Fixture·Carriage 등 주변 객체를 3D 공간 상에서 관리할 수 없는 한계가 있었습니다.

특히 Tool 장착 옵션을 설정할 때는 3D 파일을 업로드하고 ‘저장(Save)’ 버튼까지 눌러야만 화면에 반영되는 구조였습니다.

비즈니스 모델

  • B2B 스마트 팩토리 및 산업용 로봇 설비 자동화 솔루션
  • 공장 라인 기획 지원
  • 로봇 설비 3D 시뮬레이션 환경 제공
  • Factory Builder를 통한 공간 구성 도구 제공

핵심 리스크

  • 업로드 → 저장 → 오류 확인 → 삭제 → 재선택의 무한 재작업 반복
  • 3D 공장 설비 구성 리드타임 지연
  • 현장 세팅 간섭 검증 오류로 인한 인스톨 공수 손실
  • 추가 인건비 리스크 발생

Business Insight: 3D 시뮬레이션이라는 핵심 가치를 제공하고 있었지만, 저장 전 미리보기가 불가능한 구조가 오히려 반복 작업을 유발해 리드타임과 비용 리스크로 이어지고 있었습니다.

타 3D 툴(Blender, Rhino, Sketch 등) 비교 분석 결과, 타 툴은 2D UI와 3D 공간을 오가는 전환 지점(객체 선택, 좌표 조작)에 표준화된 기즈모/카메라 패턴을 제공하는 반면, 자사 서비스는 2D-3D 전환 및 실시간 피드백 정책 자체가 부재함을 발견했습니다.

정성 인사이트: “저장 전에는 툴이 로봇에 어떻게 장착되는지 볼 수 없어 매번 저장과 삭제를 반복해야 해 피로도가 극심하다.” — 내부 코어엔진팀 및 비전문가 사용자 UT(3차) 공통 피드백

원인 분석 결론: 표준화된 전환 인터페이스와 실시간 피드백의 부재가 사용자로 하여금 저장-삭제를 무한 반복하게 만드는 구조적 원인이었습니다.

가설 · Hypothesis

Tool·Fixture·Carriage 객체의 실시간 수정/Draft 확인 페이지를 제공하고, 2D-3D 전환 인터페이스(Gumball/기즈모, 카메라 컨트롤)를 표준화한다면, 반복 작업 퍼널과 조작 소요시간이 단축되어 비전문가 사용자의 3D 공간 구성 완료율 및 사용성 평가 점수가 상승할 것이다.

실시간 Draft 확인 2D-3D 전환 표준화 반복 작업 제거

솔루션 전략

전략 02

Gumball 기즈모 시각화와 카메라 제어 정책을 표준화해 2D-3D 전환의 조작 직관성을 확보한다.
전략 03
User Interaction 강화 (Identify)
여러 객체가 겹쳐 보이는 복잡한 3D 공간에서도 선택 상태를 명확히 구분할 수 있도록, 선택된 Tool·Fixture·Carriage를 아웃라인/하이라이트로 강조하고 Scene 위에 객체명·타입 태그를 오버레이해, 사용자가 지금 어떤 객체를 보고 조작하고 있는지 즉시 식별할 수 있게 한다.
06

실행 · Execution

As-is — 기존 플로우

  • 로봇 조회 → 툴 선택 → 3D 파일 업로드 → 저장
  • 저장 후에만 3D 공간에서 장착 결과 확인 가능
  • 오류 발견 시 삭제 후 툴 재선택부터 다시 시작
  • 원하는 세팅이 완성될 때까지 무한 반복

To-be — 개선 플로우

  • 로봇 조회 → 툴 선택 → 3D 파일 업로드
  • 실시간 Draft 화면에서 기즈모로 위치 확인 및 즉시 수정
  • 원하는 세팅 확인 후 한 번에 저장
  • 가동 단계로 바로 진입

솔루션 방향: 저장 전 확인이 불가능한 구조 자체가 병목이었기 때문에, 실시간 Draft 뷰어를 핵심 축으로 두고 2D-3D 전환 인터페이스를 표준화하는 방향으로 설계했습니다.

저장 전 실시간으로 Tool·Fixture 위치를 확인하고 조작할 수 있는 Draft 뷰어가 적용되어, 유저가 원하는 세팅을 시각적으로 즉시 인지하도록 하려는 기획 의도가 성공적으로 전달되었습니다.

결론: 성공. 불필요한 저장-삭제 반복 루프가 사라져 유저의 작업 연속성과 공간 구성 완료율이 획기적으로 향상되었습니다.

레슨런 · Lessons

L1

정책과 기능 방향을 먼저 정의해야 실행 단계의 혼선을 막을 수 있다

복잡한 3D 전용 인터페이스 및 다직군 연동 기능을 기획할 때, 착수 전에 전체 데이터 구조와 개발 기술 제약을 선제적으로 파악하고 정책 방향을 명확히 정의하는 것이 실행 단계의 공수 낭비를 막는 핵심임을 체득했습니다. 단순히 빠르게 실행하는 것이 아니라, 개발 목표와 기존 정책을 전반적으로 파악한 후 기획을 시작하는 것이 중요하다는 것을 깨달았습니다.

L2

기술 제약을 사전에 맞추면 기획의 완결성과 실행 속도가 함께 올라간다

이후 프로젝트에서도 표면적인 UX 개선에만 그치지 않고, 착수 전 개발팀·코어팀과 기술 제약 및 데이터 연동 기준을 사전 Sync하여 기획의 완결성을 높이고 데이터 기반 가설 검증을 주도하겠습니다.
